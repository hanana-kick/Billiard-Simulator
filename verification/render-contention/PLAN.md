# Frozen renderer contention diagnostic

Baseline deployed d21e9ec2260f7c23e220a2e17baed81a5cf39380. No product changes.
18 sequential fresh Chrome attempts: fixed three/four-ball requests × receive-only / real UI idle / real UI orbit × 3 balanced repeats. Same physics engine, solver and full-rest successful replay. All attempts/failures retained. Search deadline is diagnostic3600000ms with120s infrastructure watchdog, unchanged from previous measurement.
Each attempt has5 seconds pre-search observation; orbit uses external trusted CDP mouse with left buttons; idle sends no pointer changes. During search same orbit cadence200ms, periodic external click probe as previous measurement. UI idle does not synthesize input. UI orbit renderer-consumption preflight required. Receive-only is not a renderer-identical causal control; combined UI versus no-UI costs cannot prove an individual cause.
Collect host OS/CPU/memory, Chrome version/flags, SystemInfo GPU feature and device fields, actual render-worker WebGL vendor/renderer/context attributes. Software GPU/headless findings do not generalize to Android/Mac hardware.
Collect render submit/return/draw timestamps, worker render wall, serialization, input sequence receipt, dirty/pending/inFlight state, produced/drawn frame cadence, rAF callback-entry cadence. Draw is canvas command boundary, NOT actual presentation/display FPS. One in-flight/latest pending source contract checked; queue snapshots are sampled at render calls, not a proof of every instant.
Compare pre-search versus search same workload, process user+system CPU deltas where supported and retained process identity; terminated-process missing cost is a lower bound. CDP traces separate main tasks/GC, render worker wall vs CPU, and GPU process. No sum of overlapping slices or claim GPU-process CPU is GPU hardware execution time.
No candidate is preregistered. Only evidence of unnecessary render/backlog can justify a separately frozen candidate. No blind frame throttle, physics changes, main deployment, or relaxed correctness. Source backend introspection and wrappers are diagnostic only; timing overhead remains a limitation.
