# Isolated pressure-recovery experiment

No baseline files edited, no build/deploy/push. Apply pressure-recovery.patch to a disposable copy of candidate, or overlay the three src files. Baseline optimizer-service SHA-256 is e0258591997e15531f7dfe310fa81557904cc9f9f2589abc082b0321d8850ae2. Full baseline/output hashes: sha256.json.

Behavior: existing initial 250 ms grace, pressure thresholds (>120 ms once or three >40 ms frames within 1200 ms), worker pacing (8 ms/16-step blocks, 4 ms yield), physics, planner files, admission and foreground promotion unchanged. Automatic recovery requires 750 ms continuous visible moving frames <=40 ms with no observation gaps >40 ms. Hidden/paused/late/invalid frames reset the healthy interval. Completed/promoted/canceled/disposed jobs cannot recover. Every renewed pressure episode can immediately suspend again.

Retained wake is intentionally limited to the CPU event and CPU event-window planner identities, a live cooperative coordinator, a paused unfinished/noncancelled search.core with finite deadline, and an unfinished staged wrapper. It clears only search.core.paused and search.pausedAt. It never calls the general planner resume API, never grants a new budget, and leaves original absolute search.core.deadline and core.started unchanged. Unsupported planners remain suspended until ordinary foreground promotion. If original deadline expires during suspension, recovery can finish the retained in-flight evaluation but cannot grant another search window; normal planner deadline checks still govern subsequent work.

No live world/evaluator replacement, execution generation change, request restart, wave reload, worker-pool expansion, foreground promotion or main-thread computation occurs during recovery. Facade message generation advances to reject obsolete messages. A result that raced with suspension is reissued on recovery rather than lost.

Bounded browser evidence fields on service.job: pressureSuspensions, pressureRecoveries, lastPressureAt, lastRecoveryAt (monotonic performance.now milliseconds). Fields are absent until the first event. pressureRecoveries counts issued recoveries, not worker acknowledgments. Actual acknowledged worker evidence: optimizer.retainedState.backgroundRecoveries, backgroundRecoverySteps, backgroundRecoverable, suspended, inFlightSteps/inFlightCandidateId; final result cooperativeRetention includes actual recovery counters. No unbounded event history.

Verification: node --test pressure-recovery/tests/*.cjs: 65/65 pass. Includes existing lifecycle/coordinator/worker-pool tests and new repeated pressure, sustained recovery, hidden/paused/gap reset, cancellation/disposal/promotion guards, stale message generations, completion races, original deadline, unsupported planner refusal, exact evaluator identity and mock result/trace/work equivalence. These are focused harness tests, not real-app browser or physical replay validation. Full real-app Chrome, physics suite and build remain unverified for this experiment and are required before any release.
