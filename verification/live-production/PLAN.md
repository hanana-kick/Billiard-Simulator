# Live production actual-Chrome qualification

Canonical URL read from pinned repository README: https://dangoo.hananakick.cc/ . Pages workflow deploys dist only after its unchanged build/physics/full desktop+mobile E2E gates. This harness does not replace those gates.

FIXTURE=default3/default4/moved3/moved4 selects a predeclared4-case shard, two viewport sizes × two repeats; no filter runs all16. Fixed16 cases: two repeats × desktop1280x850/mobile390x844 × default3/default4/moved3/moved4. Repeat1 reverses viewport/fixture order. Each case has an isolated fresh browser context, then a normal same-context reload to observe cache behavior. Chrome sandbox stays enabled. No user persistent browser data used, no uploads/deployment or production source writes by this harness.

Actual UI mode buttons, actual pointer ball drags for moved fixtures, actual Search/Resume/Stop/Apply/strike. World coordinates are read through existing renderer projection; no move/controller action or searchGoal injection. Narrow means CSS viewport, not a physical touch-device claim; moved fixtures use real mouse pointer events at both viewports. Initial/submitted actual world snapshots and hashes are recorded; cross-viewport pointer placements need not be byte-identical, and comparisons must disclose differences.

At most four additional actual20s Resume slices, observed at most25s each within100s overall. Additional identity qualification is explicit and separate from mandatory lifecycle pass; zero additional identities must not be described as proven second-route recall. Separate realUI cancellation probe. Apply checks every candidate setting and proves no strike/position change. Actual gameplay must reach full rest and score1 within45s. Independent replay in fresh PhysicsLab/real gameplay rules caps40000steps, kept separate from live CPU. No physics edits or cloned source injection.

Cold and normal-cache reload must match pinned embedded controller/planner/optimizer/next-shot/physics/forecast hashes. HTML and received JS/CSS/WASM bytes hashed, network cache/service-worker evidence captured. JSX route-planner hash is release-source provenance only, not falsely asserted as embedded compiled UI hash. A production-built asset manifest can supply further exact compiled UI matching if available.

Read-only state and CDP100ms CPU observations only: no timer/worker/controller wrappers. Process CPU is shared-process sampled lower bound, not per-worker attribution. Report mean/median/range by fixture/viewport with n2, source/snapshot equivalence, sampled wall, first recall and additional identity denominators. All failures/screenshot/JSON retained; exit nonzero if any mandatory assertion fails. No lucky reruns or threshold changes.

After actual gameplay reaches full rest, eight seconds of next-shot/route state are observed. This may show activity but does NOT prove automatic promotion provenance, in-place reuse, retained worker identity, or all promotion states. Those remain uncovered unless additional existing-source evidence proves the real handoff. No automatic-promotion behavior is forced.

Scope exclusions: not all settings permutations, physical mobile/touch browsers, every fixture or promotion state. Existing main full E2E remains mandatory. Worst-case16-case run can require roughly90minutes including boot, so use120minute job limit or split fixed fixture shards without retrying failed cases.
