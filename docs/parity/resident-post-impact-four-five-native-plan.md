# Held four-versus-five macro native diagnostic

## Boundary and authority

This is a **component diagnostic from an explicitly declared, owned HOST h192
state**, not a raw shot or raw-to-impact GPU acceptance. The only physical input
is the existing immutable `post-impact-profile-v1/initial.v8`, SHA-256
`05f78ef994c2b69960e8e64c07d03cd17c0947656d573afee82820d764a5ff5e`.
Its original source-PC begin bookkeeping already declares one additional h;
physical h/dt/caps, source order, full history and audit words are unchanged.
The ordered two rows are accepted219 and rejected522. A fresh VM begins in each
pass; no old VM words are relocated, and no h193 expected values enter execution.

The source-owned four-macro baseline and optional fifth `rc_raw_program_step`
body/guard remain unchanged. No new merged core, phased numeric mode, ISA,
initialization or physics path is introduced. Native qualification and speed are
**pending**. Preserve the four-macro baseline if five is not actually faster.

## Closed files and roles

- `*-input.v8`: exactly kind/profile/source-initial hash, six current h192 source
  bindings, and immutable bytecode. No template, expected output, old VM,
  convenience CPU trajectory or callback. All logical lengths/hashes are checked against fixed original binding digests, not merely a caller-provided hash.
- `*-plan.v8`: shader text, exact source approvals/configuration/layout, fixed
  schedule and input digest. Core WGS64; handlers WGS1. Full original configuration and generated shader hashes are independently pinned in the lean contract. No physical data arrays.
- `*-assertions.v8`: own-profile HOST final six bindings and **entire** VM state,
  plus the separately captured unchanged original PhysicsLab h193 endpoint.
  Native execution never opens these files.
- `manifest.json`: frozen source file hashes, independent file hashes and sizes,
  preparation invocation, command/allocation bounds and explicit diagnostic scope.

The native entry imports only the closed contract, lean transport and process
identity. Compiler, source generators, fixture, native CPU oracle and comparator
imports occur only in the prepare/assert command branches. The original source
input remains unopened until all pipelines compile **and** an explicit matching
`go` decision arrives. `abort` and decision expiry execute zero dispatches.

The held receipt binds profile, actual native invocation, manifest, plan and
input hashes, plus the ready-file hash. Unknown or mismatched fields reject.
It carries no source/VM state, physics status or work-budget override. This is a
local process contract, not cryptographic provenance of arbitrary third parties.

## Fixed schedule and resource ordering

Each profile gets a **fresh dedicated device/process**. Only its compiled
pipelines survive between its two independent fresh-buffer passes. No devices,
pipelines or evolved banks are reused across the four/five profile boundary.
This bounds retained compiler objects and makes cross-profile timings separate
context measurements, not a calibrated hardware ratio.

| Profile | Unique preflight modules | Pipelines | Fixed cycles/pass | Compute dispatches/pass | Both passes |
|---|---:|---:|---:|---:|---:|
| four | 5 | 6 | 108 | 1 +108×5 =541 | 1,082 |
| five | 6 | 7 | 96 | 1 +96×6 =577 | 1,154 |

The identical core module is preflighted once, then reused for begin/pump.
**All** unique `compilationInfo` checks finish before the first expensive
pipeline. Pipeline order is broad handler first, core begin/pump, cue, numeric,
coupled and (five only) Number-program. No source buffers exist during compile.
After the held barrier, each pass uploads six source arrays plus bytecode into
fresh buffers; the VM allocation is zeroed by the device and original begin.
It executes begin once, then the fixed core/ID-ordered handler sweeps. No per-h
mapping, intermediate result decision or CPU forward work occurs.

Both completed passes copy all eight buffers (six source, bytecode, VM) into one
preallocated combined readback. There are **16 copies, four submissions and one
final map per profile**. A pass's buffers are released only after compute/copy
drains; the retained readback preserves its completed output, never a runtime
input for pass2. Eight storage buffers are simultaneously bound.

Four explicit live storage plus combined readback peaks at28,557,528 bytes;
five at28,389,336 bytes. These are declared buffer bytes, **not** measured free
memory or compiler/driver resource bounds. Compiler RSS/exit/signal must be
captured externally by the coordinator. Normal, aborted and failed invocations
release the dedicated device. Queue-loss cleanup still attempts a drain and
destroys all owned buffers; SIGKILL cannot execute JavaScript cleanup.

## Assertions and timing

After native completion, a separate process requires:

1. Every word of six source bindings, including readonly arrays and full audit,
   equals that profile's immutable HOST final.
2. Entire VM controls, PC, counters, locals, stack and immutable code equal that
   profile's own result; no normalization between four/five layouts or counters.
3. Both fresh passes exactly repeat.
4. The unchanged original h193 projector (`7c467cb`, integrated515eb34) passes all
   eight represented groups: balls, cue, clock, rules, history, game, partialOuter
   and complete accepted emissions. The original partial outer remains outer3,
   next outer ordinal4/substep1; no outer completion or scorer step is invented.

Cold preflight/compile, initial upload, compute encode/finish/submit/queue-drain,

## HOST gates and commands

Seven focused HOST tests pass (no GPU): actual input stripping and identity,
unknown/future/changed data rejection, held-decision binding, preflight-before-
pipeline failure, fake-device fixed schedule/one-map/fresh-bank lifecycle,
queue-loss cleanup, and assertion-only existing HOST endpoints against the
unchanged original eight-group projector. Fake-device tests execute no physics.

The coordinator captures resource/exit evidence and decides whether to launch
five after four. Neither failure nor a longer path silently extends work.
