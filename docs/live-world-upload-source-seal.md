# Experimental upload-only host-source seal

This is an opt-in build facility, not an application default or GPU qualification.
The normal source module exports `LIVE_WORLD_UPLOAD_SOURCE_SEALED=false` and
`LIVE_WORLD_UPLOAD_SOURCE_REVISION=null`. A caller cannot enable upload-only graph
reuse by passing a hash, boolean, object, or copied receipt to the runtime.

## What is pinned

`tools/build-live-world-upload-seal.mjs` traverses every static relative import
and re-export from three explicit roots: the audited public entry, current live
batch implementation, and upload preparer. The complete transitive modules are
pinned as full UTF-8 source strings, including all original host factory code,
WGSL literals, packers, admission/identity code, and the inactive seal stub.
Conservative whole-module pinning intentionally invalidates the seal even for
unrelated edits inside that closure. Unknown/nonlocal imports, computed/dynamic
imports, `require`, `eval`, and direct `Function` construction are rejected. Symlinked or escaped
source files are rejected. The parser is a closure-discovery tool, not a sandbox
for executing malicious JavaScript.

A review candidate is generated by the exported
`createLiveWorldSealReviewCandidate(root)` helper and explicitly marked
`UNREVIEWED`. The build has no automatic refresh/accept-drift option. A reviewed
repository pin must be established separately after code review. Its review
marker records that workflow; it is not a digital signature or protection from a
malicious actor who can rewrite both the build tooling and approved repository.

## How the browser artifact is authorized

1. `verifyLiveWorldSourcePin` validates the exact closure membership and every
   source byte against the reviewed pin. A digest is only a reporting identity;
   it never substitutes for byte comparison.
2. Verification creates an opaque build capability owned by a private WeakMap.
   Copied metadata, caller-constructed tokens, and runtime hashes are not accepted.
3. The esbuild plugin loads exclusively from that private verified snapshot.
   Neither the source filesystem nor caller pin is reread during bundling, so a
   post-verification edit cannot replace a vetted module (TOCTOU).
4. Only the exact approved inactive stub is substituted with immutable sealed
   constants and the source revision. The checked-in audited entry exports the
   batch/helper APIs and bundle-owned contract/raw/world namespaces, not the seal.
5. One self-contained browser ESM bundle is produced with a separate artifact
   receipt (exact bundle SHA-256, byte length, source revision and module count).
   Deployment must serve this vetted artifact rather than reconstructing modules
   from the receipt. Minification is allowed because provenance comes from build
   inputs, not runtime `function.toString()` or filesystem inspection.

The trusted boundary is the reviewed repository/build and the delivered artifact.
This is not a claim that arbitrary hostile JavaScript sharing the same page, an
altered build tool, or a replaced bundle can be made trustworthy by metadata.
Build dependencies/tool versions remain part of the existing trusted build
installation; receipts do not claim independent reproducible-build verification.

## Validation

`node --test tests/live-world-upload-source-seal.mjs` covers unreviewed pins,
source-byte and closure-membership drift, dynamic/external/escaped imports,
forged capability tokens, source/pin mutation after verification, privileged
stub substitution, and successful minified/nonminified snapshot builds.
Runtime upload-only parity and complete source-closure review are separate gates.
No approved source pin or source-sealed browser bundle is claimed merely because
these synthetic build-mechanism tests pass.

## Opt-in runtime contract

`createExperimentalLiveWorldBatchGPU` defaults to `preparation:'full-capture'`.
`preparation:'sealed-uploads'` is rejected by ordinary direct-source imports;
only the verified self-contained artifact has the internal immutable grant.
Caller flags, digests, or fabricated capabilities cannot enable this option.
The sealed path captures one original graph, derives each candidate's original
56-byte uploads, and overlays those uploads on fixed assets. At N3, the two
identity allocations are explicitly candidate-local; at N1, sharing remains
valid but a replacement candidate overwrites both original identity uploads.
Widths remain limited to N1 and N3.

`buildRevision` is returned on the engine and each run. A consumer may supply
`expectedBuildRevision` to require the same artifact source revision; mismatch
rejects before compilation. This is a compatibility check against an already
verified internal build, not authorization from a caller-supplied digest.
Existing full source/graph/layout and guarded-recipe comparisons remain in place.
Search and selected execution must bind the same reviewed source build and
compatible exact recipe; no application/session default is switched here.

Bundle modules own distinct WeakMaps, so bindings must be created by that same
bundle's `rawWorld` and `worldContinuation` exports. The native harness recreates
those owned bindings from the exact canonical request and original clock, keys,
and local options; it does not reuse direct-module-owned binding tokens.
