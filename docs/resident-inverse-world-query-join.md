# Opt-in resident legacy inverse scalar join (HOST source proof)

**Implemented source, not a qualified GPU producer or enabled solver adapter.**
`source-four-ball-inverse-query-join-v1` joins the actual same-world observation
state, existing original physical-rule bank, and original raw-clearance result
into the optional 64-word/256-byte inverse-terminal-observation v1 record.
No CPU forward call, supplied success Boolean, expected future state, per-step
readback, replay, or default/UI activation occurs in this module.

## Admission and identity

`createInverseWorldQueryJoinPlan({observer, initialization, prepared, request,
topology, rows, purpose, generationId})` returns `{plan, context, inputs}`.

* `observer` is an authenticated **v2** same-world producer plan, never the
  superseded enlarged-view v1. `initialization` is the existing locally branded,
  immutable source creation plan, including the full native initial history.
* `prepared` must pass `assertPreparedLiveFourBallCandidate` against the **whole**
  request snapshot. Matching native bytes alone would not bind restored object
  IDs/radii/handles, clock, events or material parameters; metadata swaps reject.
  Both created and prestrike identities must match the initialization owner.
* Four-ball/carom only; explicit fixed/search elevation and spin constraints;
  original inverse private request validation, target/method overrides, per-shot
  rule fields and 8/16/30-second horizon are checked. The fixed source outer dt
  remains `1/960`. No normalization, clamping or clearance restoration is added.
* Any `request.finalization` is rejected. This is the historical **source query**,
  not `source-gameplay-finalization-v1`. The latter needs its own versioned result
  identity and actual original game-finish evidence, not a flipped Boolean.
* Exact Number-bit request/topology identity (including signed zero), immutable
  raw settings/IDs, source generators, original projection functions and source
  physics identity feed the contract digest. The full physical runtime/shader
  manifest must still be pinned independently; this digest alone is not proof
  of execution or source authenticity on an arbitrary device.

Call `assertInverseQueryInitialInputs(plan, inputs)` immediately before upload;
all raw input words and sealed initial plan views are rechecked. Typed arrays
are not made immutable by `Object.freeze`. This assertion is an initial upload
contract, **not yet wired into a live GPU runtime**.

## Original buffers are not enlarged

The source generator reads existing physical state (source binding 0), raw
inputs (4) and disjoint observation storage (5 / physical GPU binding 7). Code
and VM remain physical bindings 5 and 6; there is no ninth binding.

The final 64 words reuse the producer's convex-query output and alignment tail
**only at a completed observation boundary**. They never alias physics,
program, original numeric scratch, frame, episode state or observation
projection. For the two-stage/capacity-256 example, the record is at observer
word 2432 in the unchanged 2496-word allocation. It is not appended to any
original logical view; source arrayLength and invalid-address semantics remain
unchanged. Existing mandatory emission-audit plus observer composition remains
explicitly unsupported until a separately proved logical-view partition exists.
Do not remove that independent tape gate to admit this profile.

`generateInverseWorldQueryJoinWGSL(plan)` creates a bounded candidate-local
terminal kernel. A future runtime may schedule it at a predetermined GPU
boundary after retained physical work; no CPU branch on world results is needed.
It does not mutate world/rule/input banks. This task does not add that dispatch
to the current execution path.

## Exact source join / fail-closed publication

For evaluated records, source world/outer terminal seals, original rule fields,
raw accepted-creation transcript, full sampled/cast-clearance completion counts,
selected identity, and observer h/epoch/projection checks are mandatory. Positive
physical success requires the original rule success flag without invalidity and
no-cue/all-asleep full-rest flag. A goal then additionally requires the exact
ordered observation prefix and all original inequalities. `verified` is true
only for the explicit `verify` purpose. Physical rest here is the original
four-ball search boundary, not a new actual-gameplay receipt.

The nine values are original `[-clearance, ...inputInequalities(request, settings)]`
in the same order. Software binary64 subtraction/absolute value preserves Number
rounding and signed zero. `hypot2` is the existing exact source helper bound to
**V8 13.6.233's fast-hypot binary64 profile**, not a universal browser/JavaScript
claim; its original V8/SunPro attribution is retained. The already-source-ordered
reducer supplies nullable residual availability, prefix, first-object cell and
its original division-then-Math.round value. That value retains -0 internally;
only the final cell field normalizes zero to +0 because the original
`JSON.stringify([id, dt, rounded])` does so. Residual/inequality signed-zero bits
are not normalized. No idealized cushion or fabricated
residual is introduced here.

World status running/uninitialized becomes transport-incomplete, physical
incomplete remains distinct, and cancelled/unsupported/failed records contain
no scalar payload. Rejected raw candidates are **unsupported by this accepted-
raw-only join**, never ordinary physical misses. Finite validated evaluated
negatives retain their genuine source observations. Malformed or stale protocol
state cannot reuse an old successful projection. The evaluated status is written
last. No miss is substituted for missing replay, device failure or unsearched
space.

## Evidence and limits

The focused test runs generated WGSL through the existing scalar HOST VM using
independently modeled binary64 primitives. It compares **every 256-byte record
word** to unchanged `inverse-events.js::projectResult`, independently exercising
the original physical accumulator and resident rule reducer. Positive, negative,
late-foul, purpose, fixed/search elevation, spin, signed-zero, tiny input, null
cell and malformed-state cases are included.

Those terminal component banks are **explicitly discrete protocol witnesses**,
not claimed physically reachable trajectories. Actual native execution in these
tests is limited to original initial capture/clearance with no forward h. The
separate producer v2 test proves genuine created-t0 and two-h same-world frames;
it does not establish raw-to-rest scalar qualification.

The clearance reuse prerequisite separately exercises four actual settings
under both unchanged `FourBallGame.contact` and inverse
`observePhysicalEvent` callbacks. Original `cueClearance` reads only ordered
`[...statics, ...objects]`, selected sphere/settings, old collider shapes/poses
and handles. Strike allocates cue/guide bodies and emits stroke without stepping
or changing that roster. All read-set values and original before/after clearance
results compare exactly in eight bounded no-step witnesses, with the pinned
physics source SHA. Arbitrary callbacks and changed source are not admitted.
This supports the source read-set argument; it is not universal GPU numerical
qualification or proof of every possible input.
