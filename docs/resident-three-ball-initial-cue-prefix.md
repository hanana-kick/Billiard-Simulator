# Genuine-three numerical initial cue prefix

`three-ball-initial-cue-prefix.mjs` replaces **current cue body input authority**
with an actual original-initial → pre-solve numerical producer. It does not
replace rigid exclusion, floor geometry, deferred cue joint solve, world
transactions or native parity.

## Interface

- `createThreeBallInitialCuePrefixPlan(template)` accepts only the exact local
  branded created-owner template.
- `executeThreeBallInitialCuePrefixForTest(plan,{testOnly:true})` runs the
  unchanged `cue-orchestration.executeCueForTest(mode0)` instruction programs.
  Inputs are the original cue bank, selected real sphere and **exactly two**
  genuine other sphere body64 rows. No fourth body or expected state is supplied.
- `assertThreeBallInitialCuePrefixResult(result,{template})` checks actual result
  identity, exact template identity, source identity, plan/program integrity and
  every completed word against its private seal. A copied result/receipt, a
  separately repacked same-hash owner, mutation or detached storage is rejected.
- `result.layout.{cue,cueWords,bodies}` identify the only produced owner ranges
  intended for composition. Words preserve original template addresses and append
  a 32-word control block. The scene registration region is unchanged:
  `registrationRegionUntouched=true`. The cue bank's 90 numeric registration
  output words are ready and compare exactly to the separate initializer.

## Executed source order

The existing mode0 source programs execute other-sphere separation, current
COM, binary64 lateral prefix, binary64 compliant-tip prefix, original numeric
registration, then binary64 clocks/stats and deferred-solve bookkeeping. A
distinct genuine-three bridge maps the complete current cue bank into canonical
shaft3/head4. It retains localCOM56 versus worldCOM59, registered extent62 and
thickness63, exact inertia, damping, forces, role generations and unused ABI
sentinels. The three actual sphere rows remain unchanged in the admitted initial
non-touching profile.

The original `Cue.prepareApplication` is executed **after** candidate production
only for independent comparison, with `original-js-number-v1`. No source current
body, clock, initialization array or future result is copied into candidate words.
All 144 source joint/guide input fields, all 90 numerical registration outputs,
complete canonical cue rows, exact mutable API call order and binary64 clocks are
compared. `sourceExpected` is diagnostic only and is not a producer input.

The mode0 output has `frame=1`, `outerSubstep=1`, `needsSolve=1`: it is a genuine
**deferred pre-solve** boundary, not a completed h. Existing numerical joint output
must subsequently be adopted exactly once; calling another joint solve is not an
adoption implementation. This module does not perform that later adoption.

## Scope

Both original cue selections and the immutable after-turn ready-world input are
valid prefix fixtures. Prefix success for selected-1 does **not** remove its later
empty-cue-contact ownership blocker. After-turn keeps the actual g3 cue handles
and original application time; no projected future is relabeled as t0.

Execution is a HOST interpreter of the unchanged source-number/f32 programs,
not runtime/GPU qualification. Broad/BVH producer integration must explicitly
consume the branded produced ranges, retain its own exact registration check,
and continue to declare any HOST exclusion/floor-geometry dependency. No world
commit, full h, physical step or native internal endpoint is claimed.
This prefix does not independently run the inactive pre-CCD checker
(`inactiveCcdPreOwned=false`); the later genuine cue/CCD owner remains responsible
for that source predicate, rather than inferring it from this body's low speed.
