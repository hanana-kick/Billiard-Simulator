# Exact eight/nine-row diagnostic gate: four independent passes

**The frozen count8/count9 × macro-WGS1/WGS8 profiles passed their independent
original-created-t0 and isolated-source-h2 comparisons.** This is a bounded
source/version-specific diagnostic result on fallback SwiftShader, not general
GPU qualification, compact publication, full-rest/1,024-row execution or a speed
claim. No production qualification flag or default backend was changed.

The [curated evidence](evidence/resident-scale-eight-nine-validation.json) binds
all four exact source, bytecode, core, runtime, gate, reference, actual and
independent-PASS hashes. It contains metadata only: no raw state banks, logs,
future snapshots or absolute private paths. Nothing was uploaded or published.

## Physical and lane scope

- The fixed roster was not reduced or replaced. Count8 retains six admitted and
  two rejected rows; count9 retains seven admitted and the same two rejected.
- All eleven owners are compared at original created t0 and two genuine source
  h-steps, with original JavaScript Number cue/application reference, dt1/960,
  subdivisions64 and outer0. The original thirteen-call created-t0 authority and
  accepted/rejected history are retained. This is not a Controller outer-step.
- Every VM row completes without error, pending macro or residual stack. A fixed
  budget ending incomplete would fail, never become an ordinary physics miss.
- Macro-WGS8 count8 runs one group with no padding. Count9 runs two groups with
  seven guarded padding lanes; actual admitted ID825 is invocation8. Thus the
  second-workgroup boundary is exercised by a real row, not empty padding.
- Each WGS8 result is bit-exact to its **same-count independently passing WGS1**
  full world/VM/scratch at both captures. No six-row baseline identity is reused.
- Core WGS64, four exact source macros, preparation disabled, no event-audit
  binding, source budget32768, core budget65536, h2 and512cycles remain fixed.

## Negative evidence remains part of the record

1. The first count8/WGS1 independent assertion failed **before h2 comparison**
   because the adapter called the historical helper intentionally restricted to
   six rows. The old six helper was not weakened. The [assertion-only repair](resident-eight-nine-comparator-repair.md)
   added closed8/9 source/roster admission, with byte-identical per-row/control/
   all11/tail comparison body. Wrong-count, duplicate-ID, missing-row and other
   negatives passed; replay of unchanged actual/reference bytes passed. The
   failed log and corrected receipt have distinct preserved hashes.
2. After the first three profiles passed, the retained process received SIGKILL
   during the **first count9/WGS8 broad pipeline**, after all26 compilation-info
   checks and before any count9/WGS8 execution grant/dispatch. Session peak RSS
   was1,934,112KiB. The cause is unproven; this is not diagnosed OOM or a numerical
   failure. Successful preceding artifacts were preserved.
3. Exactly one separately approved [fresh-device resource-context recovery](resident-nine-wgs8-fresh-device-recovery.md)
   compiled the unchanged count9/WGS8 plan all26cold/0warm, waited for its own
   explicit decision, executed the fixed schedule and exited0. No failed cache,
   prior future state or successful schedule was reused/replayed. Peak RSS was
   1,670,976KiB. Its independent full9-row/baseline-bit-parity receipt passed.

The cold recovery result does not erase the retained-session resource failure.
Both are relevant to allocation/cache lifetime policy at larger scale.

## Remaining release gates

This closes the intended eight/nine lane-boundary diagnostic, not the release.
Early/late events, full physical rest, broader varied input coverage, real hardware
and practical resource/cost limits still need separately approved evidence.
Larger counts need fresh count-specialized source/runtime/limit admission;
1024 must not be inferred from these rows or from allocation-only two-bank
planning. WGS8 is not adopted as a performance default. Compact production and
public PASS/MISS publication remain unqualified. No next native run is implied.
