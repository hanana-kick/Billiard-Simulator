# Compensated cue lateral prefix

Four tests pass against the unchanged PhysicsLab lateral method and original native impulse APIs. Across30 prepared states, both scalar double-single and actual WGSL have zero maximum absolute impulse and velocity error. Each retains23 signed-zero representation differences. This is a standalone prefix gate: it advances0ms and does not certify a stroke, joint recurrence or three-ball world.

The original velocityAtPoint results remain native f32. Only the application's JS Number operations use the shared approximately48-bit double-single graph: displacement and relative-velocity projections on the original double-valued cue axis, lateral spring/damping combination, and multiplication by the original double h. The impulse crosses to f32 once at the public native API boundary. Native impulse application, torque cross product and inertia multiplication retain source f32 operation order. This is not a generic joint motor, a force-model change or full binary64 emulation.

The independently executed original method supplies expected impulse and post-API body velocities. The source-double diagnostic is separately required to match those observations. Prepared states include horizontal, product-default8° and three oblique/high-elevation orientations, transverse offsets, angular/linear motion, zero coefficients and bounded non-default coefficients. These are deliberately isolated lateral-only fixtures: sphere iteration is omitted and obstruction admission is bypassed solely to observe this component. They are not untouched whole-scene strike-admission evidence.

Admission requires finite exact f32 body state, coordinates/COM within±10m, linear velocities within±100m/s, angular velocities within±1000rad/s, nonnegative inverse mass at most1000 and inverse-inertia components within±1e8. The original JS axis must be unit length within1e-10. Supported h is1e-6 through1/960s, stiffness0 through5000, damping0 through10. More extreme inputs reject explicitly before the eager double-single graph can overflow. There is no all-input or all-device accuracy guarantee; shared-helper midpoint/subnormal limits remain.

API: compensatedReference(input), sourceReference(input), and await createGpuStage(device), followed by stepBatch(inputs). Input/output shapes match the previous lateral prefix. The validated ordinary f32 path remains unchanged, and the created-state/common-world owner is not switched by this checkpoint. A later integration requires its own original-native recurrence comparison at the existing fixed gates: impulse2e-6 and body velocities3e-6. Zero signs are reported separately, not silently normalized.

Actual shader compilation, dispatch and storage-buffer readback ran on Dawn/Vulkan SwiftShader.
