# Source-created cue preprocessing

The bounded numerical preprocessing gate passes 5/5 without skips, including independent original-native API comparisons and actual WGSL readback. This validates preprocessing only, not a solved first-h trajectory or full three-ball scene.

The numerical stage accepts the unchanged source-created shaft, head and fixed guide before the first strike h. It computes collider world transforms, world center of mass/effective inverse mass/inertia, and the new bodies' max_extent using the same f32 operation graph on scalar and WGSL. CCD thickness is already initialized by collider insertion and is checked, not falsely treated as a missing post-h value.

Local mass is retained by a narrowly checked source identity: fresh bodies start with default local mass and no additional mass; insertion folds their enabled colliders in attachment order. The first queued mass recomputation resets to default and repeats exactly the same unchanged fold, then adds default additional mass. This preserves the actual source eigen result for the head. Its translated zero-mass neck is not structural zero and must not be omitted. This specialization is not a general mass/eigen implementation. Changed shapes, local poses, mass parameters, enable states, attachment order, locked axes or additional mass are rejected.

Pending manager and joint work is distinct from numerical body preprocessing. New body flags are all-changes, max_extent is initially zero, and body IDs may be invalid until user changes registers them. Initial joint link events and later mutable-joint events are serde-skipped: only an explicit source call journal can establish them. A serialized snapshot is not proof that those transient queues were restored. The first application transition also changes world dt to h=dt/64 and applies the lateral/tip method before engine preprocessing. Nothing here substitutes an original native first step as the implementation.

The first numerical fixture deliberately removes two balls, moves the selected ball to x=.4 and executes 72 additional application steps after the constructor's own 72 native settling steps. Original static table/cloth/cushions and physical equations/descriptors remain unchanged, but this is an altered single-ball layout, not the original three-ball scene. A separate native creation probe retains all three constructor placements with no additional settling, move or removal. The original source accepts the product-default strike on the original white ball: angle0, elevation8, speed2 and centered tip, without bypassing clearance. Its initial application time and cue elapsed time are zero. The first native h is retained only as an independent comparison target. The numerical gate covers both the controlled horizontal single-ball fixture and the product-default elevated three-ball creation pose. Source-owned host-u32 preprocessing also matches native body registration, exact allocator free stacks,13 joint connectivity events, final link order and removal-journal resolution. The energy scan remains a separate phase. Full common-h integration of all three ball components is not established by this gate.

The first numeric gate compares world COM/collider poses/inertia at3e-6, effective inverse mass/max_extent/CCD thickness at2e-6, and attachment mass identity exactly. No acceptance limit was changed. Native body/collider initialization calls are prepared-phase references, not substitutes for the first integrated engine step.

initializeUserChanges accepts only created initial state, roles and the explicit source event journal; native post-state is rejected. It returns source-user-changes-and-connectivity-complete-pre-collision without clearing flags early. finishCollisionPhase requires the common owner's owned collision admission, clears the consumed source flags and resolves only the bounded fresh never-sleep cue removal journal. It does not implement or certify collision detection itself. General manager mutation/sleep/split and fresh cue rigid-contact generation remain outside this component.
