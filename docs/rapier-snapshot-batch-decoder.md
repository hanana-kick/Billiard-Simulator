# Read-only framed snapshot decoder

The separate batch executable and asynchronous wrapper pass seven tests. For the same immutable saved snapshots, the complete typed serde trees, successful native JSON payloads and independently re-encoded bytes match the unchanged single-shot decoder. Every frame retains both strict checks: native bincode byte roundtrip and independent JavaScript typed-tree byte re-encode. Invalid snapshots return explicit errors; malformed framing, truncation and oversized declarations terminate the session. Fragmented streams and valid/corrupt/valid recovery are tested.

This is only an oracle-transport utility. It does not step physics, change a world, infer omitted workspaces, reduce observation frequency, inject native state into a candidate, or modify the original CPU engine. The existing single-shot Rust source, JS wrapper, executable and provenance remain untouched. The new binary includes the exact original main.rs inside a private module, directly reusing SnapshotWorld, Typed, Compound, float-bit encoding and source constants. Only the short decode/check/export orchestration and framed transport are separate.

Protocol: launch the distinct binary with --batch-v1. Each request is a four-byte little-endian byte length followed by exactly one native snapshot. Each response has the same framing and a JSON envelope containing protocolVersion 1, the sequential zero-based index, and either the original result object or an explicit error. The successful result schema remains 1. Frames are checked in order, including input SHA256 and byte length. Float values remain exact hexadecimal bit strings, preserving signed zero and NaN payloads rather than converting them to JSON numbers.

Limits are 1..32 MiB per input, 256 MiB per response, 8192 requests and 1 GiB total input per session. The wrapper admits at most four pending requests and defaults to a 30-second per-request timeout. EOF is valid only between frames. A partial response, unexpected process exit, duplicate/reordered response, wrong source/engine identity or failed byte check rejects without unchecked fallback.

Usage: require tools/rapier-snapshot-batch-decoder, then createBatchDecoder({engineVersion:'0.21.0',binary,provenance}). Await decoder.decodeSnapshot(bytes) for each immutable snapshot; await decoder.close() when all requests finish. abort() terminates pending work. decodeSnapshots(iterable,options) is an asynchronous generator. Initial vendor, binary, included source, new batch source, manifest, lockfile and build-script hashes are verified once for the immutable session. The original encodeLosslessTree implementation is reused for every frame.

The explicit build helper validates the same official Rapier/Parry archives and source manifests and builds only --bin rapier-snapshot-decoder-batch. It records toolchain, feature list, build profile, source hashes, new executable hash and original executable hashes before/after. The original executable is required to remain byte-identical. No Cargo manifest/lockfile or original source edits are needed.

A small three-snapshot measurement, 123040 input bytes total, took 836.05 ms through separate single-shot decodes and 890.54 ms through one batch session, including each path's full roundtrip verification. Therefore no speedup is established. Process startup and repeated vendor hashing are removed, but native deserialization/re-serialization, tree construction, JSON transport and JS re-encoding remain. This sample is not a throughput or hardware-performance claim. Physics capture paths are not switched by this checkpoint.

Native build/equivalence proof: the original single-shot source and executable remain unchanged; the new binary exposes included/new source SHA256 values in --version and a separate snapshot-batch-decoder-provenance.json.
