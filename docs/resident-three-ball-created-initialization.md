# Genuine-three created registration: bounded HOST/source plan

One **created-world → user-changes/connectivity-complete, pre-collision** source
plan, not a numerical world owner, first-h implementation, native mid-stage
observation, GPU qualification or runtime integration.
`nativeRegistrationBoundaryVerified:false` and `preCollisionOnly:true` remain
explicit. All whole-h/whole-shot/default flags are false. Existing four-ball
packers, generators, CPU gameplay/search and defaults are unchanged.

## Source audit and exact reuse

- `browser-initial-import/live-initialization.mjs:53–162` already exports the
  three actual cue numeric descriptors through
  `exportRegisteredCueInitialization(input,'three')`. They come from owned,
  byte-verified created data and original zero-step creation calls, not future
  initialized values.
- `experimental-cue-initialization.js:15–48` supplies the unchanged-attachment
  mass validator and exact 40-input/30-output f32 graph. General mass/eigen
  recomputation is unsupported. `numeric-program.mjs` compiles/executes it
  unchanged, without pruning, reordering or reassociation.
- `scene-initialization.mjs:66–82`, `rc_scene_created_initialize`, consumes three
  numeric receipts and actual modified queues. Its exact 1/2/0 shaft/head/guide
  collider counts, incoming-first cue adjacency and two joints fit genuine-three.
- `scene-activation.mjs:86–114,246–249` uses native body slots/generations and
  allocator maps. Its 32-body/6-dynamic limits are capacities;
  `rc_scene_capacity` counts actual dynamics and accepts <=5. The special
  six-dynamic cue-component restriction is not a five-dynamic prerequisite.
- Both existing scene WGSL generators are reused **without edits or string
  rewriting**. The existing linker preserves reachable function bodies verbatim.
  No collision/energy/solver/full-h call is emitted by this plan.

Headers remain **22 live bodies, 5 dynamics, 25 colliders**: three spheres,
shaft/head, fixed guide and the original table. Unused capacity is zero/inactive,
not a fourth sphere. The graph's uniform 30-word results include unused
attachment-output slots; only actual 1/2/0 attachments are registered. Scratch
outputs are not additional physical colliders.


`three-ball-host-admission.mjs` privately retains the existing exporter's
numeric inputs, bound to the locally branded registration. Its public shape and
old control-layout words remain unchanged. New
`three-ball-created-initialization.mjs` returns a distinct
`resident-three-ball-created-initialization-plan-v1`, with sealed initial/program
words, original control layout, exact history, preserved-f32 source shader,
single-invocation descriptor and explicit unsupported capabilities.

Original f32 values retain their bits on packing. Native u32 identities and
generations never become floating handles. Binary64 application clocks and full
event history are retained unchanged. No raw parameters, strike, clock increment,
native allocation or physical integration occur. Numeric outputs start empty;
all three graph results must be ready before registration. Separate completion
is published only on successful registration, not as whole-world completion.

Copied/forged registrations or plans, changed/detached input/program words,
caller-provided outputs and non-test HOST execution are rejected. Outputs are
not new admission authority. Missing-ready-mask, malformed joint-chain and replay
failures remain unsupported, never physical MISS. The HOST interpreter is not
a runtime fallback.

## Independent numeric evidence, distinct from registration evidence

`tests/resident-three-ball-initialization-source-fixture.cjs` is a separate
ORIGINAL process importing no resident/source-port initializers. Both original
selectable cue captures reproduce independent original `fire()` created bytes.
It optionally reads the immutable existing after-turn input at
`/tmp/three-ball-live-evidence-20261025/capture.after-turn.v8`; no new fullshot is
prepared.

A separate native clone of each created snapshot calls only
`recomputeMassPropertiesFromColliders()` for shaft/head/guide,
`propagateModifiedBodyPositionsToColliders()`, and `takeSnapshot()`.
`world.step` is forbidden. Before those APIs, an independently decoded restored
snapshot must retain every field of all 22 bodies and all 25 colliders. Native
restore/reserialization is **not assumed byte-identical** (serialized lookup
order may differ). Neither restored nor prepared snapshots seed the plan or its
managers/queues. Original initial input remains unchanged.

For cue1, cue2 and immutable after-turn fixtures:

- **189/189 native values are bit-identical**, 63 per fixture: world COM,
  effective inverse mass/inertia, maximum extent, CCD thickness and every actual
  cue collider pose. Attachment-fold local mass remains exact. No tolerance
  relaxes the native comparison.
- All 90 generated numeric output words per fixture match the original source
  graph exactly, including unused source output slots.
- The complete decoded registration equals the established
  `initializeLiveRegisteredThreeBallUserChanges` source initializer: managers,
  free lists, body/activation data, collider poses, consumed/remaining queues,
  13-event joint journal, two links and four removals.
- Actual recycled shaft/head/guide handles `21:g3 / 19:g3 / 20:g3` remain intact;

  binary64 clocks/rule identity are unchanged.

**Limit:** manager registration is compared against the established source-port
initializer, not an independently observed native internal boundary. The public
native API exposes the numerical operations above but not that mid-world manager
boundary. `nativeRegistrationBoundaryVerified:false` is therefore retained
explicitly. No first-h/future state is relabeled to conceal the gap.

## Still unsupported

- General geometry/material/mass/mutation, allocation growth, arbitrary raw
  candidates, later-state inputs or continuation beyond the admitted initial
  source boundary.
- Collision finalization, broad/narrow geometry, CCD, integration, scoring,
  search termination and physical rest. Consumed queues and modified flags remain
  pending for the separately unowned collision work.
- Whole-world schema/owner: `requireThreeBallResidentOwner` still rejects, and
  this distinct plan cannot substitute for four-ball world-h.
- GPU compilation/execution and device numeric qualification: generated WGSL is
  structurally linked only. Selecting preserved-f32 is not a hardware proof.
- Independent native registration-boundary parity, fullrest parity and release
  gates. No default activation or publication.
