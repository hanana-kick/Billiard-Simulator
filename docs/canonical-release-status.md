# GPU 기준 canonical 엔진: 릴리즈 상태

2026-10-28 02:30 UTC 로컬 소스·기록 기준. **실험적 구현이며 앱 기본 엔진
전환, GitHub 업로드, 배포 또는 릴리즈 완료를 의미하지 않는다.** 아래 수치는
각각 명시된 체크포인트의 증거이며, 변경 중인 작업 트리 전체에 자동 적용되지 않는다.

## 기준과 검증을 분리한다

검증된 GPU용 canonical 물리 모델을 실행 기준으로 삼고 CPU 구현은 같은
수치 규약을 재현한다. CPU의 기존 Rapier 궤적에 GPU를 맞추는 작업이 아니다.
CPU/GPU 정수 일치는 실행 정합성의 증거이며, 물리 모델의 타당성 증거를
대체하지 않는다. 물리 법칙, 충돌·규칙, 완전한 샷, 실제 앱을 별도로 검증한다.
전역 누적 오차 증명은 canonical-local 프로필의 필수 성공 조건이 아니다.

이 direct-candidate 모델은 과거 resident 네이티브 엔진 이식 실험과 다른
경로다. `resident-release-gates.md`의 원본 엔진 재생 요건이나 과거 inverse
릴리즈 설명을 이 모델의 완료 증거로 사용하지 않는다.

## 물리·선택 샷에서 확인된 범위

- 실제 타격 입력에서 전체 공 상태를 정지까지 이어 계산하는 무득점, 득점,
  득점 뒤 상대 공 접촉 반칙의 개별 샷에 CPU/GPU 정수 일치 증거가 있다.
  물리 REST와 게임 PASS는 별도 결과다. 모든 충돌 조합을 지원한다는 뜻은 아니다.
- MMQ2 구름·공·유한 쿠션·정지 이벤트를 합성한 **준비된 3구 세계 6사례**에서
  상태·밀집 상태·두 저널의 **15,552개 정수**가 일치했다 (`4276300`).
  실제 쿠션 1회/2회 후 REST, qy 정지 후 pending, 쿠션 후 미해결 pending을
  구분했다. pending을 MISS나 REST로 바꾸지 않았다. 준비된 세계의 검증을
  원시 타격·4구·득점 전체 범위로 확대하지 않는다 (`canonical-world-mmq2.md`).
- MMQ1/SWG1 선택 샷의 득점·큰 u32 ID 득점은 각각 **159,744개**, 득점 뒤
  반칙은 **204,800개** 원본 기록 정수가 일치했다. 취소·기록 용량 초과 후
  재사용도 검증했다 (`canonical-selected-gpu-source.md`).
- MMQ2/SWG2 최종 강화 소스 (`6223fbb`, 증거 `39bf17f`)는 실제 4구 원시
  타격의 쿠션 1회 후 REST에서 **31기록 / 63,488개 정수**가 일치했다.
  별도 준비된 세계의 쿠션 1회 REST, qy 정지 후 pending, 쿠션 2회 REST도
  각각 **26,624 / 22,528 / 206,848개** 원본 정수가 일치했다.
  저장된 GPU 기록의 hydration은 CPU 물리 계산과 점 표본 계산을 금지한
  별도 검증도 통과했다 (`canonical-selected-swg2-integration.md`).
- 기록 완결성·물리 결과 완결성·구간 표본 완결성은 별도다. 모든 후보의
  전체 궤적을 저장하지 않으며, 선택 기록에도 표본이 없는 내부 구간에서는
  정확한 점을 만들어내지 않는다. MMQ1의 취소 검증을 MMQ2 배치에 전용하지 않는다.

## 릴리즈 전 남은 조건

1. 현재 연결된 유한 파라미터 탐색의 폭·분기·수명주기를 확장 검증한다.
   기본 실험은 N3 반복 배치이며 수천 개 동시 처리의 완료 증거가 아니다.
2. 미지원 입력·형상·재질과 종료 조건을 명시한다. 원시 타격 지원 범위는 UI보다
   좁고, 누적 work/event 예산은 아직 실제 강제되지 않았다. 애매한 충돌,
   미수렴, 예산 소진을 MISS/REST로 바꾸지 않는다.
3. 충돌이 있는 no-kiss 전체 경로, 실제 3쿠션, 모드별 공·규칙 범위를 추가
   검증한다. 준비된 개별 사례와 raw 전체 샷의 증거를 혼동하지 않는다.
4. 현재 제공되는 명시적 새 게임 이외의 배치 편집·설정 가능한 탐색 영역과
   거부되는 실제 앱 편집 기능을 해결한다.
   수동·미리보기·탐색·history의 상태 소유권을 일관되게 유지한다.
5. 최종 코드의 빌드·물리 회귀·실제 앱 브라우저 검증을 통과한다. 작은 화면,
   설정, 한국어 폰트 로딩, 취소·반복 조작을 포함한다. 실제 browser WebGPU
   옵트인 엔진 실행은 일반 앱 UI 검증과 별도 필수 조건이다.

현재 컨테이너의 sandbox 유지 Chromium 시작은 페이지가 열리기 전에 OS
socket `EPERM`으로 실패한다. HTTP 200·테스트 발견·host harness는 브라우저
통과가 아니다. GitHub Actions 경로와 실제 버튼 기반 별도 browser smoke가 준비됐지만
실행/통과는 확인되지 않았다.
백업 브랜치 쓰기는 도구 거부 후 추가 확인 대기 상태이며, 로컬 커밋을 push로
표시하지 않는다. 메인 변경·배포·릴리즈는 하지 않았다.

## 성능과 실행 환경

native WebGPU 증거는 **SwiftShader 소프트웨어 Vulkan**이며 실제 하드웨어
처리 시간·가속 배율을 입증하지 않는다. 과거 1024 compact의 약359초,
현재 봉인 N3의 전체 약210초/컴파일 약182초는 서로 다른 작업의 단일 측정이다.
약 1.4GiB의 프로세스 RSS를 후보 상태 버퍼 크기로 설명해서는 안 된다.

`local-hardware-benchmark.md`의 측정 도구는 과거 고정 프로필 기반이다.
현재 소스의 실제 하드웨어 비교를 위해서는 동일 작업·프로필을 다시 묶고
CPU/GPU 시간을 각각 측정해야 한다. 측정 전 임의 배율 환산은 하지 않는다.

## 탐색 영역을 사용자가 편집하는 경로

선택적 GPU 모드의 수동 탭에서 조준·속도·들림·타점 X/Y의 유한 값 목록을
편집하고, 실행 전에 정확한 곱셈 조합 수를 볼 수 있다. 기본값은9개이지만
최대4096개의 대기 후보를 지정할 수 있다. GPU 동시 폭은 여전히 N3이며
잔여 후보는 N1이다.4096후보 native 실행 완료를 주장하지 않는다.

중복·비유한값·축 범위·총개수 위반은 적용 전에 거부한다. 잘못된 편집은
진행 중 검색을 취소하지 않는다. 유효한 새 영역을 적용하면 이전 후보와
검색은 무효화하지만 공 위치·게임 점수·history는 바꾸지 않는다. 타점의
합성 반경0.6을 넘는 조합은 총수에 포함하고 미지원 개수를 별도로 표시한다.

입력은 Q24 편집 해상도로 저장하고 표시용 Rapier 상태를 다시 읽지 않는다.

배치 후 기존 검색·미리보기 결과는 무효화하며, 물리 REST 영수증을 새로 만들지
않는다. 원래 누적 시각·게임 상태는 유지하고, 한 드래그의 완료·취소 및
되돌리기/다시 실행에서 소유 상태를 복구한다. 잘못된 입력과 변경 없는 입력은
검색·히스토리를 보존한다. 69개 집중 호스트 검사가 통과했으며, 이 편집 기능을
실제 브라우저 또는 새 네이티브 GPU 실행으로 검증했다는 의미는 아니다.
높이·재질·공 추가/제거·초기화·게임 규칙 변경은 여전히 이 모드의 지원 범위 밖이다.

## 초기화와 쿠션 프로필 선택

`8c8390f`는 canonical 초기화로 해당 세션의 시작 배치·게임·타격 설정·시각을
복구하고 기록을 비우되, 편집한 검색 조합은 유지한다. 실행 중 요청을 취소하고
완성된 초기화 상태만 화면에 알리며 요청 식별자는 재사용하지 않는다.

새 게임은 MMQ1(기본) 또는 유한 쿠션을 지원하는 MMQ2를 명시적으로 선택한다.
필요한 저장 버퍼는 각각 9/10개이며, 프로필을 기존 게임 중간에 바꾸지는 않는다.
MMQ2의 기존 개별 샷/배치 증거는 이 새 진입→검색→적용→타격 전체 흐름의 검증을
대체하지 않는다. 해당 전체 흐름의 GPU 검증은 아직 남아 있으며, 예산 초과나
미지원 결과를 MISS로 바꾸지 않는다. 이 변경의 집중 호스트 검사는 63개가 통과했다.
