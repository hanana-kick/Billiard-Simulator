This is a **HOST source-component checkpoint**, not a physical h, native internal

## Executable composition

`createThreeBallFirstNumericalPlan(firstScenePlan)` accepts only the local branded,
sealed initial first-scene plan. `executeThreeBallFirstNumericalForTest(plan,
{testOnly:true})` accepts no timing, roster, geometry, physical output or future
state. It reconstructs the original initial transaction; an already-produced
result is never a continuation input.

1. Execute the existing authentic 22-body / five-dynamic / 25-collider first
   collision boundary. Keep all native handles, generations, queues and t0 history.
2. While its original cue/broad/journal/floor leases are still live, prepare the
   original `original-js-number-v1` cue application, with joint solve deferred.
   The original floor owners supply current geometry only; no solver is invoked.
3. Check source enabled-CCD **pre-force** predicates for every awake sphere and
   retain the actual two cue prechecks. Sleeping sphere checks are skipped exactly
   as the source world does. Active pre-CCD is unsupported. The f32 interval must
   equal `f32(application.dt / strokeSubsteps)` and every original body/cue dt.
4. The distinct genuine-three energy entry admits only the sealed first collision,
   exact five canonical bindings and shaft/head rows **3/4**. It reuses unchanged
   `scene-world.mjs` force/energy gather → lowered numerical evaluation → writeback
   functions, with the original scene active-order, resets, manager/free queues,
   sleep transitions and effective-force order. No pose integration is performed.
5. If complete current manifold metadata exists, apply source floor hint updates
   and original persistent solver-roster ordering. Run the distinct three-sphere
   gather into `coupledStateLayout(3,18)`. Three is the true physical sphere count;
   18 is contact/catalog capacity, not a fourth body. Awake sphere compaction is in
   canonical sphere order; solver contact order is the native persistent buckets.

`three-ball-first-numerical-source.mjs` is an internal differential dependency:
original Scene/Hint/Roster execute independently from the emitted integer and
lowered numerical path. Expected observations are compared, **not packed into the
resident scene**. Current prepared cue/floor fields and hints are HOST source-owner
inputs, not yet resident numerical-geometry implementations. The original source
`MathSource.pack` independently verifies every common/body/contact gathered input.

## Endpoint and timing limits

The executable endpoint is **post-force/energy, optional solver-input gather,
pre-cue-joint/pre-sphere-solve**. Numerical force and possible sleep velocity
writeback are real; no sphere pose, solver impulse or world state is committed.
`requireThreeBallFirstNumericalContinuation` always throws explicit unsupported.

The interval is the **original initial-h inactive-source-precheck interval**, not
an invented constant and **not a CCD-selected solveDt capability**. The legacy
three-ball source observes energy with this interval after inactive prechecks.
The general CCD pass, source TOI/split selection, and post-solve CCD checks are not
composed here. `ccdPassAuthorityVerified=false` and
`nativeSelectedSolveDtVerified=false`. No bare `createAuthority/selectPass` call
manufactures proof from a guessed `firstImpact=null`.

Deferred source ordering matters: `experimental-four-ball-world.js:219–220`
executes the actual two-dynamic cue joint owner before the sphere contact solve;
the legacy genuine-three owner solves cue joints even earlier in cue preparation.
Thus this checkpoint **does not dispatch the coupled solver** before the missing
cue owner. `three-ball-solver.mjs` retains a distinct three-body scatter function
as unqualified component groundwork only; unfinished-solve tests prove it cannot
write canonical rows. Completing those rows would still not mean a whole world h.

All native internal-boundary flags remain false. This is not native first-step or
outer-step parity. PhysicsLab's latched outer subdivisions remain a separate gate.
