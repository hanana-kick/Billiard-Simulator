# Genuine-three initial current-pose rigid exclusion

`three-ball-initial-rigid-exclusion.mjs` is a distinct emitted-source owner for
all **25 original colliders and 54 source-filtered cue/obstacle pairs**. It does
not change the four-ball geometry module or supply contact/manifold ownership.
No GPU, completed-h, arbitrary recurrence or full-rest qualification is claimed.

The factory accepts only the authentic three-ball created-owner template. It
packs immutable source initial descriptors, original hull vertex order and the
unchanged `Guard.buildPlan()` program. Current poses come from the five real
canonical dynamic rows, not immutable initial pose words or source expectations.
The begin stage takes the same current-pose snapshot as original `Guard.check`;
finish rejects a changed input bank. Exact cue prefix state and the complete
25-collider generation registry are checked, without a caller-provided admission
flag.

## Ordering and boundaries

1. All 54 original support/analytic graphs are evaluated in source pair order.
2. All 54 results are classified in original order before any GJK refinement.
3. Fast support separation is accepted only from the original graph result.
4. Ambiguous canonical sphere/cylinder pairs use the original strict
   `signedDistance > sphereRadius + prediction` predicate, not a reordered
   subtract-radius/contactShape comparison.
5. Ambiguous cylinder/fixed-box-or-hull pairs use the unchanged source query,
   all 256 original GJK iterations, EPA and finish stages. A null result alone
   does not prove separation: the owner requires completed support-lower-bound
   metadata and a finite bound strictly greater than prediction plus BAND.
6. Completion requires all 54 individual proofs. The tip/cloth row is **not
   delegated or skipped**: without a distinct cloth owner, it must fast-separate,
   otherwise the original unbound-guard behavior is explicit unsupported.

Unknown contacts, malformed generations, numeric/cap failures and unavailable
proofs are unsupported, never inactive contacts or ordinary shot misses. This
owner does not solve the selected-1 extra empty cue manifold-cache gap.

## Composition API and resources

- `createThreeBallInitialRigidExclusionPlan(template)` exposes sealed
  `initialWords`, `program`, `geometryWords`, `scratchWords`, `layout`, `rows`.
- `generateThreeBallInitialRigidExclusionWGSL(plan,bases)` emits the control seam.
- `buildThreeBallInitialRigidExclusionSource(plan,bases)` emits all twelve
  source stages and the immutable schedule, plus a linked source entry for
  scalar microcode lowering. `bases` contains exactly
  `{stateBase,programBase,geometryBase,scratchBase}`.
- A same-bank composer calls emitted stages on its produced cue/body words.
  No HOST geometry decision, receipt, or forward callback is part of that path.
- Isolated `...ForTest` harnesses are explicitly test-only; only the locally
  produced prefix harness can issue an identity- and complete-word-sealed result.

Actual fixed allocation: **1,344 candidate words**, **9,576 immutable geometry
words**, **25,910 original graph program words**, **13,632 reusable scratch
words**. These are allocation sizes, not measured GPU throughput or residency.

## HOST evidence scope

All three authentic initial captures are compared against independent original
`Guard.check` and every one of the 54 original support-graph output rows. They
currently require 54 fast proofs each, including the actual tip/cloth row.
Separate current-pose component holdouts exercise the real analytic boundary and
strict GJK refinements; those mutated test banks receive no authentic initial
receipt and are not trajectories. Native cue-pose holdouts reuse only the two
cue poses with all three genuine sphere identities and all25 original colliders.

The test microcode transport uses the existing AST-approved `NUM_EVAL` intrinsic
reference for the unchanged 5,176-node graph. Control and query source execute
as emitted microcode. The slower all-instruction test transport was stopped
without a terminal result; it is not counted as a passing gate. Neither test
transport is a runtime fallback. Actual GPU and complete-h composition are
separate gates.

Focused HOST gate: **5/5 PASS**, 26.92 seconds. In addition to all authentic
54-row comparisons, it exercises one actual analytic separation, exact analytic
threshold equality rejection, four strict GJK separations, a strict-query contact
rejection, and a tip/cloth contact rejection. First failure pair/reason survives
remaining fixed-schedule no-ops. None of these component probes qualifies an
arbitrary initial bank or whole h.
