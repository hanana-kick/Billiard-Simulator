# Billiard Simulator · 당구 연습

실제 Base UI 기반 shadcn/ui와 Rapier 3D를 사용하는 물리 실험 웹앱입니다.

## 실행

Node.js 22 이상:

```sh
npm ci
npm run prepare:engine
npm run build
npm start
# http://localhost:8787
```

빌드 결과는 `dist/` 및 `standalone.html`입니다. 실제 React·Base UI·물리엔진은 함께 번들됩니다. 글꼴은 버전을 고정한 공식 Pretendard Variable CDN을 사용하며, 연결 실패 시 일반 sans-serif로 표시합니다. `dist/`를 정적 호스팅할 수 있습니다.

## GitHub Pages

저장소 **Settings → Pages → Build and deployment → Source = GitHub Actions**를 한 번 선택해야 합니다. 이후 `main` 푸시는 `.github/workflows/pages.yml`을 통해 빌드·회귀·실제 브라우저 E2E를 통과한 경우에만 배포됩니다. 설정 전에는 공개 사이트가 활성화된 상태가 아닙니다.

검색 기준 주소: https://dangoo.hananakick.cc/

`public/CNAME`과 canonical·Open Graph·JSON-LD·사이트맵은 이 주소를 사용합니다. 도메인을 변경할 때 함께 수정해야 합니다. DNS 연결 및 HTTPS 인증서 발급은 호스팅 설정에서 별도로 확인해야 합니다.

설정을 변경한 뒤 Actions의 **Test and deploy GitHub Pages → Run workflow**로 실행할 수 있습니다. PR에서는 테스트만 수행하고 배포하지 않습니다. 실패한 검사의 스크린샷·trace 및 브라우저 보고서는 `browser-evidence`, 빌드 결과는 `compiled-app` artifact에 보관됩니다.

## 화면과 조작

`경로 탐색 / 수동 / 설정`은 공식 shadcn/ui 사이드패널의 탭입니다. 넓은 화면에서는 접을 수 있는 Sidebar, 작은 화면에서는 열고 닫는 Sheet를 사용합니다. 탭·패널을 바꿔도 물리 월드, 공 위치, 타격 설정과 계산 결과를 유지합니다.

- 경로 탐색: 3구·4구 프리셋, 경로 계산과 모든 검증 후보 적용. 세부 조건은 ‘상세보기’에서 조절합니다. 계산·적용만으로 발사하지 않습니다.
- 수동: 수구·타점·큐 속도·조준·기울기, 재생과 공 배치.
- 설정: 표시, 재질·중력, 접촉 기록.

수구 앞쪽 직선을 드래그하면 조준 방향이 즉시 바뀌고, 당구대 바깥 바닥을 드래그하면 시점이 회전합니다. 공이 조준선과 겹치면 공 이동이 우선합니다. 빈 당구대 클릭은 전방 조준, 실제 큐 드래그는 반대편 조준입니다. 빈 천 전체를 드래그하는 동작으로는 조준하지 않습니다. 타격은 당구대 콘텐츠 아래의 ‘타격’ 버튼으로 실행하며 드래그 거리로 세기나 발사가 결정되지 않습니다.

공을 드래그하면 별도 배치 모드 없이 옮길 수 있으며, 이동 취소와 다시 실행을 지원합니다. 모바일에서도 두 손가락 확대를 지원합니다. 공이 움직이는 동안 큐는 숨겨집니다. 경로는 기본적으로 직전 타격만 표시하며, 모든 타격 경로 보기를 켜면 보관된 이전 기록도 표시합니다.

## 한국어 검색과 에이전트 탐색

당구 연습·3구(삼구)·4구(사구)·3쿠션(쓰리쿠션·스리쿠션) 검색에 맞춰 한국어 제목·설명, 공유 메타데이터와 WebApplication JSON-LD를 제공합니다. 한국 4구 연습의 간단한 점수·차례 표시는 제공하지만, 대회 전체 규칙이나 공식 채점을 지원한다는 의미는 아닙니다.

`public/guide.html`은 JavaScript 없이 읽는 사용법·모델 한계 안내이며, `public/llms.txt`는 AI 에이전트용 기능·용어·문서 링크입니다. `llms.txt`는 탐색 보조 문서이지 검색 노출 보장이나 크롤러 접근 제어 표준이 아닙니다. `robots.txt`와 `sitemap.xml`도 함께 배포합니다. `public/` 파일은 빌드 시 `dist/`로 복사됩니다. 안내 문서는 정적 배포 디렉터리에서 제공되며, `standalone.html` 단일 파일에는 포함되지 않습니다.

## 검증

```sh
npm test
npm run test:provenance
google-chrome --version
npm run test:e2e
```

E2E는 별도 모형 UI가 아닌 실제 배포 빌드에서 실행합니다. 세 탭과 상태 유지, 모든 설정의 접근·값 반영, 9개 재질 슬라이더의 실제 표시·키보드 입력, 다양한 CSS 화면 크기와 200% 글자 확대, 터치·핀치 취소, 3쿠션 검색·적용·타격, 공 이동과 실행 취소·재실행, 외부 실행 코드 미사용과 실제 Pretendard Variable 한글 로드를 검사합니다.

`BROWSER_EXECUTABLE`로 설치된 Chromium 경로를 지정할 수 있습니다. `APP_URL`은 이미 실행 중인 정적 서버의 주소입니다. 네트워크 탐색이 제한된 환경에서는 `LOCAL_HTML=/절대경로/standalone.html`로 동일 HTML을 브라우저에 직접 로드해 시험할 수 있습니다. CI에서는 실제 HTTP 서버를 사용합니다.

## UI 출처와 모델 한계

`src/components/ui/`는 공식 shadcn/ui Base UI 컴포넌트입니다. base-nova 스타일의 24개 공식 registry 원본과 출처·해시는 `vendor/shadcn/`에 있습니다. 앱 고유 타점·큐·캔버스 조작만 별도로 구현합니다. 자체 Slider/Select/Switch 대체 구현을 사용하지 않습니다.

공·큐의 운동은 3D 강체 및 접촉 재질 모델의 결과입니다. 예측은 동일 물리 월드의 복제 실행이며, 경로 탐색은 유한 후보 중 최선을 찾습니다. 실제 당구대 실측 보정·전역 최적해·실물 명중을 보장하지 않습니다. 과거 문서는 `docs/`에 보존하며 현재 사용 방법은 이 README를 기준으로 합니다.

## 4구 연습과 병렬 탐색

경로 탐색 상단에서 3구 또는 4구를 선택합니다. 모드 전환은 배치와 점수를 초기화합니다. 4구는 흰/노란 수구와 적구 두 개를 사용하며, 적구 두 개 접촉 +1, 상대 수구 접촉 또는 수구 장외 −1의 명시적 연습 규칙입니다. 실패하면 차례가 바뀌며 수구를 직접 바꿀 수도 있습니다. 대회 전체 규칙이나 실제 장비 규격 보정 구현은 아닙니다.

3구 기본은 3쿠션·키스 허용·모든 경로·양쪽 공 순서입니다. 4구 탐색은 두 적구만 목표로 하며, 상대 수구 접촉 금지는 키스 허용과 무관합니다. 목표 명중 후에도 모든 공이 멈출 때까지 상대 수구 반칙을 확인합니다. 4구의 선택적 ‘3쿠션 조건’을 켜면 두 번째 서로 다른 적구의 첫 명중 전까지 수구가 쿠션을 3번 이상 맞아야 합니다.

기본 탐색은 수평 방향 360°와 들림각 0~85° 범위를 대상으로 합니다. 85°는 현재 엔진 입력 상한이며 물리적 절대 한계라는 뜻은 아닙니다. 상세보기에서 현재 들림각 고정을 명시적으로 선택할 수 있습니다. 워커 수는 브라우저가 보고한 가용 병렬도와 유한 작업·메모리 가드에 따라 자동 결정됩니다. 워커 수가 달라져도 같은 조건의 후보 계획과 검증 결과는 유지됩니다. 후보는 동일 Rapier WASM 엔진으로 검증하지만, 유한 계산 예산은 모든 연속 해·전역 최적해를 보장하지 않습니다. 병렬화는 대기 시간을 줄일 수 있지만 총 CPU 사용을 줄인다는 뜻은 아닙니다. 렌더링은 OffscreenCanvas 워커를 우선 사용하고 미지원 환경에서는 기존 렌더러로 돌아갑니다.
